## 산업기밀 유출 사례 분석
### 산업기밀 유출 개요
#### 산업기술 유출 피해 및 사례
- 포렌식 성공 사례가 적다
- 분석관의 역량 차이가 크다.  
- 간혹 증거가 아예 안나올 경우도 있다.
- 최근은 삭제 데이터 복구가 많이 어려워진 상황. 그러나 삭제 데이터 찾아서 증거 제출한 경우 있음.  
  
##### 산업기술 유출
- 한 번의 기술유출 사건으로 여파가 크다.  

  
##### 대기업에서 산업기술이 어떻게 유출되나?
- 보안 프로그램
- 협력업체에서 유출
- 모든 것을 다 막을 수는 없음

##### 최근 국내 기술유출 사례
- 삼성전자 전직 연구원 DRAM 반도체 공정 기술 유출 사건
- 삼성디스플레이 수석 연구원 설비 자료 기술 유출 사건

##### 산업기술안보수사대
- 시도경찰청 안보수사과 - 산업기술안보수사대 - 운영기획/수사1팀/수사2팀/디지털포렌식,분석/유관기관 협력
- 수사 / 분석 두 가지 업무를 모두 할 수 있어야 합류 가능

##### 해외 기술 유출 대응 방안
- 지식재산처 기술 경찰 100명 증원
  - 국가첨단전략기술 해외 유출 사건 -> 휴대전화로 촬영하여 국가첨단젼략기술 등 유출
  - 지식재산처가 적발

### 디지털 포렌식
#### 디지털 포렌식이란?
- 전자적으로 처리되어 보관,전송되는 디지털 데이터를 적법한 절차와 과학적기법을 사용해 수집,순석해서 증거로 제출하는 일련의 절차

##### 증거의 종류
- 직접 증거: 요증 사실(증거에 의하여 증명을 요하는 사실)을 직접적으로 증명하는 증거
- 간접 증거: 요증 사실을 간접적으로 추론하는 증거
- 인적 증거: 증인의 증언, 감정인의 진술, 전문가의 의견 등
- 물적 증거: 범행에 사용한 흉기, 사람의 신체 등

#### 보관 증거, 생성 증거
##### 디지털 증거
- 보관 증거: 디지털 기기에 저장된 증거. 사람이 직접 작성한 데이터
- 생성 증거: 사용자의 개입 없이, 여러가지의 디지털 데이터 처리과정에서 생성된 증거

##### 보관 증거 (직접 증거)
- 그 내용 자체가 입증하려는 사실과 바로 연결되면 직접증거가 될 수 있다.
  - ex) 범행 계획이 적힌 문서는 범행 의도,공모 사실을 입증하려 할 때의 직접증거 또는 강한 간접증거이다.
- 진정성, 무결성, 작성자 동일성이 입증되어야 증거가치가 높아진다.  

참고) 카카오톡 분석의 어려움 : 줄임말/ 키워드 검색/ 대화 내용의 방대함

##### 생성 증거 (간접 증거)
- 윈도우 아티팩트는 보통 특정 행위가 있었음을 추정하게 해주는 간접 증거이다.
  - ex) 레지스트리, prefetch, lnk, jump list, shellbag

> [!note]
> 디지털 보관증거는 전문증거이나, 케이스에 따라서 직접증거 또는 강한 간접증거로 인정될 수 있다.


#### 디지털 포렌식 기본 원칙
- 정당성: 적법하게 수집되었는가? > 제도적 통제
  - 위법수집증거 배제법칙
  - 독수의 과실이론
- 재현성: 포렌식 결과를 신뢰할 수 있는가? > 전문가, 공인된 분석 장비
  - 동일한 조건 상황에서 항상 결과가 같아야 한다.
  - 교차분석
- 신속성: 지체 없이 신속하게 진행되었는가? > 지체 없이 신속하게 진행
  - 휘발성 정보 수집
- 연계보관성: 증거 관리 연계성? > Chain of Custody
  - 증거물 획득-이송-분석-보관-법정 제출의 각 단계에서 담당자 및 책임자에 대한 명확한 이력 확보
- 무결성: 원본과 동일한가? > Hash
  - 증거가 위,변조 되지 않았음을 증명

##### 레지스트리(Registry)
 - Windows 운영체제의 설정과 선택 항목 등을 담고 있는 데이터베이스
 - 실행창에서 regedit
 - 트리 형태로 저장
 - CLASSES_ROOT: 확장자 설정, 기타
 - CURRENT_USER: 현자 로그인된 사용자 설정, 프로그램 설정
 - LOCAL_MACHINE: 하드웨어 구성 초기화 파일, 시스템의 여러 구성 값
 - USERS: 각 사용자 프로파일에 대한 값 (CURRENT_USER 포함)
 - CURRENT_CONFIG: 원도우 디스플레이 정보, 프린터 등
 - 레지스트리 하이브 파일
   - ntuser.dat -> 설치할 때의 사용자 정보
   - Amcache.hve
   - SYSTEM / SOFTWARE / SAM / SECURITY 
   - 포렌식 소프트웨어를 사용해서 레지스트리 하이브를 수집할 경우, 파일과 동일한 이름의 LOG1,2 확장자 파일도 확인 가능

    - HDD -> 플래터 하드 디스크. 복구할 수 있는 데이터가 있었음
    - SSD -> 복구가 잘 안됨. NAND 플래시 메모리
      - 가비지 컬랙션
      - TRIM
      - 속도가 우선
    - 휴대폰 -> 플래시 메모리 방식

> [!note] TRIM
> 더 이상 사용하지 않는 데이터 블록을 지우기

HDD -> 읽고 쓰기 한번에 가능  
SSD -> 읽기, 쓰기 따로 진행 (최근은 한번에 가능한 기기도 있음) 

HDD에서 파일 삭제 -> 남겨둠. 오버라이트 되기 전까지 데이터가 남아있음.  
SSD에서 파일 삭제 -> TRIM. 보통 10분 내외로 동작이 됨.  
Windows: 가비지 데이터는 필요 없다고 생각함.
