# Daily Study 작성 가이드

이 가이드는 매일 공부한 내용을 "읽었다"에서 끝내지 않고, 나중에 다시 검증할 수 있는 기록으로 남기기 위한 기준이다. 운영 순서는 매일 같지만, 글쓰기와 산출물 체크 기준은 그날 주제에 맞게 달라진다. 좋은 보안 글은 멋진 문장보다 사실, 근거, 한계, 다음 질문이 분명한 글이다.

## 하루 운영 루틴

| 단계 | 시간 | 할 일 | 남길 기록 |
|---|---:|---|---|
| Start | 3-5분 | 타이머를 켜고 오늘 산출물 이름을 소리 내어 읽는다. 책상 위에는 오늘 문서, 터미널, worksheet만 둔다. | 시작 시각, 오늘 산출물 |
| Warm-up | 5-10분 | worksheet의 `오늘의 간격 반복 복습`에 적힌 1회차 전, 3회차 전, 7회차 전 질문에 노트 없이 짧게 답한다. Week 01 Day 01처럼 이전 문서가 없으면 오늘 제목과 핵심 키워드를 훑고 "이미 아는 것 3개 / 헷갈리는 것 3개"를 적는다. | 복습 답변 2-3개 또는 사전 점검 목록 |
| Core reading | 25-40분 | 오늘 공부 자료 중 primary 1개만 고른다. 전부 읽으려 하지 않는다. | 읽은 범위, 핵심 문장 2개, 이해 안 된 문장 1개 |
| Lab | 50-75분 | 명령어, 코드, 도구 실습을 한다. 출력은 요약하지 말고 필요한 부분을 그대로 남긴다. | exact command, tool version, input path/hash, stdout/stderr, exit status |
| Output | 25-35분 | 결과물 worksheet를 채우고, 표, 로그, 그림, 짧은 writeup 중 하나를 완성한다. | 오늘 산출물 1개와 도메인별 글쓰기 초안 |
| Review | 10-15분 | 사실, 해석, 추정, 한계를 분리한다. 다음 회차 질문 2개와 3회차 뒤 다시 볼 질문 1개를 만든다. | facts/inference/unknown, 다음 질문 2개, 3회차 뒤 질문 1개 |

Warm-up의 "헷갈리는 것"은 본격 공부 전에 이미 막히는 단어를 가볍게 표시하는 것이다. 오늘 공부 중 새로 모르는 용어가 나오면 Warm-up에 계속 추가하지 말고, Review의 Unknown에 모아 다음 확인 계획을 적는다.

## 실행기능 부담을 줄이는 학습 원칙

이 커리큘럼은 의학적 치료 지침이 아니라 학습 설계다. 성인 ADHD 학습자에게 흔한 어려움은 이해력 부족보다 시작 마찰, 작업기억 과부하, 시간 감각 약화, 완벽주의로 인한 중단이다. 그래서 매일 문서는 "많이 하기"가 아니라 "작게 시작하고, 산출물을 남기고, 다음 복귀 지점을 만드는 것"을 기준으로 운영한다.

| 원칙 | 적용 방식 |
|---|---|
| 시작 마찰 줄이기 | 첫 5분은 자료 탐색 금지. 오늘 산출물 파일을 열고 빈칸 1개만 채운다. |
| 작업기억 보호 | 동시에 열 자료는 primary 1개, reference 1개, worksheet 1개로 제한한다. 모르는 용어는 즉시 파고들지 말고 Unknown에 적는다. |
| 시간 박스 | 25분 단위로 끊고, 2블록이 지나도 막히면 설치/환경 문제는 "실패 로그"로 종료한다. |
| 즉시 보상 | 매일 산출물 표, 명령 로그, 그림, 5-8문장 글 중 하나는 눈에 보이게 완성한다. |
| 회수 연습 | 읽은 내용을 다시 읽지 않고, worksheet에 지정된 1회차 전/3회차 전/7회차 전 질문에 짧게 답한다. |
| 복귀 설계 | 중간에 끊겨도 돌아올 수 있게 "다음에 실행할 명령어 1개" 또는 "다음에 볼 문서 위치 1개"를 남긴다. |

## 시간별 완료 기준

| 사용 가능 시간 | 완료 기준 |
|---:|---|
| 60-90분 | Warm-up, primary 일부, worksheet 핵심 표 1개, Unknown 1개만 남기면 성공이다. |
| 2-3시간 | 기본 루틴 전체를 수행한다. 이 커리큘럼의 표준 운영 시간이다. |
| 3시간 이상 | stretch 실습이나 reference 확장을 하되, 오늘 산출물의 품질을 먼저 확인한다. |

중간에 흐름이 끊기면 처음부터 다시 시작하지 않는다. worksheet의 "복귀 지점"만 보고 이어서 진행한다.

## 매일 두 개의 파일

각 날짜는 역할을 나누어 기록한다.

| 파일 | 시점 | 역할 |
|---|---|---|
| `week-NN-day-NN/study.md` | 공부 전/중 | 목표, 공부 자료, 핵심 키워드, 실습 질문, 산출물 체크 표를 확인한다. |
| `week-NN-day-NN/index.md` | 공부 후 | 실습 로그, 개념 정리, 사실/해석/미확인, 도메인별 글쓰기 초안을 직접 채운다. |

## 매일 반드시 작성할 항목

### 1. 오늘의 범위

- 오늘의 primary 자료 1개
- optional로 넘긴 자료
- 실제로 읽은 장, 페이지, URL, 강의 구간
- 오늘 끝내지 못한 부분

공부 자료 목록은 전부 읽으라는 뜻이 아니다. 하루 2-3시간 기준에서는 오늘 실습과 산출물에 바로 필요한 primary 자료 1개만 고르고, 나머지는 막힐 때 확인하는 reference로 둔다.

### 2. 실습 환경

- OS, VM/host 여부, shell
- 작업 디렉터리
- tool name과 version
- timezone
- 입력 파일 path와 hash
- 실습 대상이 benign/교육용/격리 환경인지 여부

### 3. Exact command block

명령어는 표에만 적지 말고, 다시 복사 실행할 수 있게 code block으로도 남긴다.

```bash
pwd
file content/_drafts/daily-study/week-01-day-01/study.md
xxd -l 64 content/_drafts/daily-study/week-01-day-01/study.md
echo $?
```

### 4. 출력과 해석

출력은 "도구가 말한 것"이고 해석은 "내가 판단한 것"이다. 둘을 섞지 않는다.

| 구분 | 작성 예시 |
|---|---|
| Fact | `file`은 대상 파일을 `UTF-8 Unicode text`로 출력했다. |
| Inference | 현재 파일은 실행 파일이 아니라 Markdown 텍스트 문서로 판단한다. |
| Unknown | `file` 명령의 판정 방식과 한계는 아직 확인하지 않았다. |
| Next check | `xxd`와 editor 표시를 비교해 실제 byte sequence를 확인한다. |

### 5. 도메인별 짧은 글

매일 5-8문장만 쓴다. 다만 매일 같은 문장 순서를 반복하지 않는다. 아래 표에서 오늘 주제에 맞는 흐름을 고르고, worksheet의 `## 6` 초안에 맞춰 쓴다.

| 주제군 | 글쓰기 흐름 |
|---|---|
| 기초/수학/알고리즘 | 정의, 작은 예제, 보안에서 쓰이는 이유, 흔한 오해, 다음 검증 질문 |
| OS/시스템 보안 | 자원/객체, 상태 변화, 권한 경계, 관찰 증거, 공격/방어 의미 |
| C/컴파일러 | 코드 조각, 빌드 조건, 실행 관찰, 차이 원인, 보안 영향 |
| 네트워크 | 데이터 출처, endpoint 역할, protocol field, session flow, 탐지 조건 |
| 리버싱 | 대상 식별, 정적 근거, 동적 근거, 가설, 불확실성 |
| 악성코드 | 격리 조건, 관찰 행위, 근거, IOC/TTP, 탐지와 오탐 위험 |
| 시스템 해킹 | target/version, trigger, root cause, primitive, mitigation/next experiment |
| DFIR | evidence source, timestamp, actor/action, confidence, telemetry gap |
| Capstone | public claim, evidence, private boundary, research value, reviewer question |

## 글쓰기 훈련 규칙

- 처음부터 완성된 글을 쓰려고 하지 않는다. 표와 bullet로 먼저 적고 마지막에 5-8문장으로 묶는다.
- "알았다" 대신 "무엇을 어떤 근거로 판단했다"라고 쓴다.
- "아마"라고 쓴 문장은 근거가 부족한 문장이다. Unknown 또는 Next check로 옮긴다.
- 공개 가능한 글과 private lab note를 분리한다. 민감한 경로, 토큰, 샘플, 공격 세부사항은 공개 글에 넣지 않는다.
- 매주 Review에는 이번 주 글 중 하나를 골라 10분만 고친다. 고칠 때는 제목, 첫 문장, 근거 표, 한계 문장만 본다.

## ChatGPT에게 리뷰를 요청할 때

아래 정보를 같이 주면 답변 품질이 좋아진다.

```text
오늘 주제: Week NN Day NN
오늘 primary 자료:
내 환경:
실행한 명령어:
주요 출력:
내 해석:
확신 없는 부분:
원하는 도움: 개념 설명 / 실습 점검 / 산출물 리뷰 / 복습 질문
```

요청 예시:

```text
아래는 오늘 산출물 초안이야.
1. 사실과 해석이 섞인 문장을 찾아줘.
2. 근거가 부족한 주장을 표시해줘.
3. 보안 분석 관점에서 꼭 남겨야 하는 환경 정보가 빠졌는지 봐줘.
4. 글을 더 길게 만들지 말고, 더 명확하게 고쳐줘.
```
